# 项目导览制作规格（用户级通用版）

> 来源：rv1126 项目 `AI_Camea_814/tour/项目导览.html` 的定稿要求（提示词模板 2026-07 整理，2026-07-14 沉淀为 skill）。
> **壳流水线复用 `work-report` skill 的 `scripts/`**（`../work-report/scripts/`，相对本 skill 目录——仓库 `skills/` 下与安装到 `~/.claude/skills/` 后两 skill 均并排，此相对路径两处都成立）：`shell_template.html`（占位符 TITLE/TOCTITLE/TOC/CONTENT，side-toc/进度条/灯箱 CSS/JS 全内联）+ `assemble.py`（片段→成品组装）+ `selfcheck.py`（自检脚本化）。两个 skill 共享视觉/交互/质量规则，差异在内容结构：报告=收口一段工作，导览=建立整体认知。
> 导览特有组件（封面 Hero、阅读路径卡、`<a class="ref">` 章节互引样式）壳模板未内置，在内容片段里附加一小段 `<style>` 实现，配色遵循第四节 tokens。

## 一、定位（先想清楚再动手）

- 这是**导览**（给新接手者 / 想理解某子系统的人建立认知），**不是工作汇报**。从总体流程原理逐层深入到各子系统细节。
- 产物 = **单个自包含 HTML 文件**（CSS/JS/SVG 全内联，无外部依赖，双击即可打开）。
- 文件名用**描述性中文/英文名，不要用 `index`**。
- 存放位置遵循项目既有约定（有 `_ai_workspace` 协作框架的项目可放对应工作区，如 `tour/` 或 `report/` 下）；无约定则与用户确认。

## 二、第一步必须深入读真实代码（别信旧文档）

- 现有 `architecture.md` / README 往往**过时**，只作线索，**所有结论以当前源码为准**，发现出入要指出。
- 摸清并梳理：入口/启动时序、核心数据流、各模块职责、线程/并发模型、关键数据结构、构建配置与开关、对外接口/协议、配置 schema。
- 高效策略：先列目录与各文件行数 → 对大文件 grep 出函数骨架 → 定点精读关键函数 → **逐条核实，不靠猜**。

## 三、信息架构（按认知弧线编排，不要按目录罗列）

- 分**部分 → 编号章节**。推荐弧线：①总览（这是什么 / 一图看全 / 技术栈与目录）→ ②运行时主线（启动 / 数据流）→ ③核心能力 → ④交互与外设/对外接口 → ⑤工程（构建 / 部署 / **演进史**）→ 附录。
- **封面 Hero**：标题 + 一段平实的总览 + 关键事实芯片 + "如何阅读"路径卡（按读者目的给几条阅读线，如"新接手 / 改某模块 / 对接接口 / 排障"）。
- 每章可独立阅读；章节之间用 `<a class="ref">` 互相引用。
- **附录**：①"我要改 X 该看哪个文件"文件地图表；②术语速查表。
- 若项目有明显的重构/攻坚历史，加一章**项目演进史**（解释"为什么这么写" + 教训），价值很高。

## 四、视觉风格（Claude 暖色书卷风，务必遵守）

- 配色：暖米白底 `#f6f1e7`、卡片 `#fffdf8`、文字 `#2c2a26`、赤陶点缀 `#b8502c`/`#c9714e`、细线 `#e3dccc`、好 `#3f7d54`/坏 `#b03a2e`/警 `#b8862c`、深暖代码块 `#2c2a26`。
- 字体：**衬线章节标题**（Georgia/Songti SC），正文系统无衬线。
- 文案**平实直叙**——标题用"这是什么/读懂 xx"这类，**禁比喻金句、禁营销腔、禁抒情**（苹果官网风、诗意大标题会被否）。
- "生动"靠**组件多样制造视觉节奏**，不是文案煽情：卡片（结论/正确/警告/教训等变体）、KPI 数字卡、阶段时间线、对照表、折叠 `<details>`、内联 SVG 流程图、代码块语法高亮、pill 标签、阅读路径卡、事实芯片。

## 五、必备交互

- **左侧固定目录** `side-toc` + **scroll-spy** 高亮当前章节（嵌套：部分标签 `.pt` + 小节链接）；窄屏自动隐藏。
- 顶部**滚动进度条** + **回到顶部**按钮。
- 所有流程图用**内联 SVG**，低饱和配色（灰 `#A8A493`/青石 `#5E7287`/橄榄 `#6B7A4F`/赤陶 `#C2562F`/坏 `#B03A2E`/好 `#3F7D54`）；每张图**点击 → 暗色灯箱放大**（滚轮缩放 + ＋/−/⟳/✕ + Esc 关闭）；灯箱 JS 只绑定 `figure.diagram .scroll`，每张图必须按 `figure.diagram > div.scroll > svg` + figcaption 结构写，缺 `.scroll` 层则点击放大/悬浮提示/横向滚动全失效。
- 以上由壳模板自带，经 `assemble.py` 组装获得，不要手写壳。

## 六、排版/布局规格（用户偏好，已验证）

- 正文字号 **~17.5px**、行高 ~1.82；衬线大标题（h1≈39 / h2≈27 / h3≈21）。
- 布局要**像网页不像窄报告**：内容区 `max-width:~1280px` **居中**，配**左侧实体目录栏**（`body` 在宽屏留出 ~272px 给侧栏，窄屏复位）。
  - ⚠️ 避免两个极端：960 窄栏会显得"两边空、像报告"；铺到 1600+ 满屏又"太宽不舒服"。1280 居中 + 侧栏是验证过的舒适点。
- 预览图随内容区宽度铺满（`width:100%`），未点开也要足够大。
- **位图截图**（产品 UI/实拍效果等）：受单文件自包含约束必须 base64 内嵌——JPEG 降采样 ~880px 宽、quality 85 控体积（画质类内容如需保真另配 1:1 原分辨率裁切）；对比场景用内联样式两列网格 + `<figure style="margin:0">` + 小字 figcaption（同 work-report 第四节"截图对比墙"写法）；img 不参与灯箱，属预期；如有原图归档，figcaption 或图墙下注明出处。

## 七、硬性质量规则（都是踩过的坑，必须遵守）

1. **章节锚点 id 不能以数字开头**（scroll-spy 的 `querySelector('#1x')` 会抛 SyntaxError 使整个脚本中断、灯箱全失效）——用字母开头的 id。
2. **SVG 框内文字必须放得进框**：逐个 `<text>` 估宽（中文 ≈ 字号 px/字、拉丁/数字 ≈ 0.55×字号、`text-anchor="middle"` 要两侧都留余量）≤ 容器宽；放不下就**加宽框 / 缩字号 / 精简文案**。**交付前对每张图全量排查溢出**。
3. **长无空格标识符**（路径、宏、`a::b::c`）给 `code` 加 `overflow-wrap:break-word;word-break:break-word`，否则会撑破窄卡片/单元格。
4. SVG 文本里的 `&`/`<` 要转义（`&amp;`/`&lt;`）；`<script>` 内的 `&&` 不用转义。
5. **交付前自检**：跑 `work-report` skill 的 `scripts/selfcheck.py`（标签配平 / TOC↔id / id 非数字开头 / SVG 溢出估算 / 无占位符残留 / 裸 `&` / overflow-wrap / figure.diagram 内 svg 带 div.scroll 包裹层），输出 PASS 才算交付。

## 八、收尾输出

- 一个自包含 HTML 文件。
- 文末 footer 注明"基于分支 X / commit Y 梳理，随代码演进可能滞后"。
- 交付后向用户复述：**章节结构** + **与旧文档的关键出入** + **自检结果**，然后等用户看过再迭代。
- 有 `_ai_workspace` 协作框架的项目：按收尾协议更新 `current_task.md` 与 `progress.md`。
