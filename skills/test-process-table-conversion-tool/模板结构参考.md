# 测试流程表版式参考

> 用途：公司测试流程表通用版式的结构说明，供 SKILL.md 第 2 步定位区块与提取功能点
> 更新规则：公司流程表版式演进时更新本文件；只写通用结构，不收录具体方案案例

公司流程表格式固定、按方案有差异。**定位一律靠锚点关键字 + 实读确认，不假设固定行列坐标。**

## 通用结构（按行序自上而下）

| 区段 | 识别方式 | 内容与提取要点 |
|---|---|---|
| 表头信息块 | 表格前部，A 列为字段名锚点 | 主板型号 / 程序版本 / 程序来源 / 软件类型 / 紧急程度 / 电压电流 / **功能描述** / 测试前准备 / 备注 等字段，值在 B 列（常跨列合并）。其中"功能描述"为多行编号文本，是功能域提取的第一来源 |
| 版本记录区 | "客户编号""本版本测试修复内容""历史版本主要修改内容"等锚点 | 版本与修复记录表格，供理解测试背景，一般不直接产出用例 |
| 测试项目区表头 | "测试类别"锚点行 | 测试类别 \| 序号 \| 测试项目 \| 检验结果（研发 / 工程 / 品质 签核列），以此确认各列实际分布 |
| 前置区块 | "客户特殊要求""特殊触发""方案受限""不视为异常"等锚点 | 特殊要求与已知限制，影响用例的前置条件与预期结果判定 |
| 菜单测试区 | "各菜单功能测试"区头锚点 | 其下 A 列（常为合并单元格）= 菜单类别名，B 列 = 序号，C 列 = 多行功能描述（含默认值、参数枚举、测试方法文档引用）。部分方案变体另有"面板基本功能""独立功能"等区块，提取方式同理 |
| 收尾区 | "不良现象记录""最终确认及判定"等锚点 | 不良记录与三部门判定（PASS / NG / 让步接收），不产出用例 |

## 提取要点

- **类别行区间**以 A 列合并单元格的范围界定，一个合并区 = 一个菜单类别。
- **参数枚举藏在描述文本里**："默认 X""范围 a-b""分别有 A,B,C 三种"等措辞即取值来源，逐项展开为用例。
- **嵌图公式单元格跳过**：WPS 制作的表格含 `=DISPIMG(...)` 嵌图公式（`data_only=True` 下读出公式串或 `#NAME?`），不含可提取文本。
- **外部文档引用**：C 列描述常引用《xx功能测试方法》类文档，能展开成步骤的展开，不能展开的在用例步骤中写明"按《文档名》执行"。
- **与本参考对不上时**，一律以实读单元格为准，并在版式确有演进时更新本文件。
