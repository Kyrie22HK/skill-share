# 测试流程表 → 测试用例表转换工具

把测试流程表 Excel 转换为带编号步骤、预期结果与分类着色的详细测试用例表。

> 来源注记：本 skill 由 WorkBuddy 生成，2026-08 标准化入库，并按公司固定流程表格式泛化（去除固定坐标与固定输出路径假设）。消费端为任意 Agent，不绑定特定工具。

## 触发时机

- 用户上传或引用被称作"测试流程表 / 测试流程表格 / 软件测试流程表"的 Excel 文件
- 用户要求"提炼功能""生成测试用例""把测试流程表转成测试用例表"
- 对话围绕某个表格提及"功能描述""各菜单功能测试"等区块名

## 客户端无关执行与覆盖核验

Claude / Codex 共用下列五步。先由当前 SKILL.md 的真实路径找到库脚本；这是 import 后传入用例的生成器，单独执行其 `--source` 提示命令不会完成转换。保留一次源表全量实读结果，后续按需要查阅，避免反复倾倒整表。

设计时在证据/制作记录维护“源 sheet/单元格 → 功能/参数/通道 → 用例编号”的对应关系；来源依据不确定的项单列待确认，不能凭已有方案记忆补业务需求。源表枚举、默认值、开关、边界、通道与限制逐项对账；用例数量不是覆盖质量的替代指标。

先列每类用例的展开依据和乘数，再生成。区分源表明确要求的组合、技能要求的逐参数/逐通道覆盖、执行者补充的采样策略；覆盖各轴不自动意味着全轴笛卡尔积。源表明确要求每种语言/比例重测全部项目时必须保留；任意顺序未给有限边界时说明有限序列的覆盖范围，不能声称穷举。观察时长、循环次数、容差和预期阈值须区分原始要求与建议，未知规格列待确认，不补造产品指标。

跨维度复测大量重复步骤时，可在规定双输出之外补“步骤定义 + 执行配置矩阵”便于审阅；每个执行编号和覆盖项必须能回到完整用例，结果仍逐实例记录。检查 RESET 或用例自身设置会否覆盖外层语言/比例，明确重设与观察时点；重复来源可共同指向一条用例。不得为缩表取消明示覆盖，也不以用例越多表示质量越高。

写入前保存源文件原件或确认已有可恢复备份；已有同名测试用例子表会被替换，先核是否含人工测试结果，非空时保全并明确本次替换范围。原始业务子表、公式、合并区域和样式应保持；宏/嵌图等特殊对象先核库支持，不能宣称无损。完成后重新打开两个输出，核用例逐行一致、编号连续、分类/步骤/预期非空、H/I 留空、分类着色和汇总；原文件占用的回退行为另验。

回读还要检查长步骤的换行、列宽和行高；数据完整不等于表内可读。无法用实际表格查看器确认时，说明未验证的视觉项，提供完整文本/参数化视图辅助审阅，不把自动对账称作人工测试执行通过。

## 环境依赖

脚本依赖 `openpyxl`。环境缺失时先向用户说明并征询安装方式，不擅自安装系统级依赖。

## 工作流程

按顺序执行，**绝不跳过第 1 步的数据检查**。

### 第 1 步　读取并检查源表

1. 用 `openpyxl.load_workbook(path, data_only=True)` 加载工作簿。
2. 打印 sheet 名、行列数、合并单元格范围。
3. 逐格读取主表全部非空单元格值，建立对整表结构的完整理解。

### 第 2 步　定位区块、提取功能点

**不依赖固定坐标**。用首列（通常 A 列）锚点关键字定位区块，再实读确认：

| 锚点关键字 | 区块含义 | 提取方式 |
|---|---|---|
| 功能描述 | 表头块内的功能总述（同行 B 列，多行编号文本） | 按编号行切分，每项一个功能域 |
| 各菜单功能测试 | 菜单测试区起始 | 区内 A 列（常为合并单元格）= 菜单类别名；B 列 = 序号；C 列 = 多行功能描述 |
| 测试类别 | 测试项目表头（序号 / 测试项目 / 检验结果） | 确认各列实际分布 |
| 面板基本功能 / 独立功能 | 部分方案变体才有的区块 | 每格 = 功能名 + 描述 |

流程表的通用版式结构与提取要点见同目录 [模板结构参考.md](模板结构参考.md)——**动手提取前先读它**；与实际表格对不上的，一律以实读单元格为准。

**提取规则：**

- **参数全覆盖**：描述文本中"默认 X""范围 a-b""分别有 A、B、C 三种"即参数枚举源，每个可选项一条用例。
- **多通道全覆盖**：多通道 / 多实例功能逐一覆盖，不抽测。
- **恢复默认覆盖**：每个可配置菜单至少一条恢复默认 / 恢复出厂用例。
- **边界用例**：参数最小 / 最大值、开关两态、不同操作方式等边界必测。

### 第 3 步　设计用例

每个功能点设计一个用例 dict，6 字段：

```python
{
    "category": str,       # 测试分类
    "item": str,           # 测试项目名
    "purpose": str,        # 测试目的
    "preconditions": str,  # 前置条件
    "steps": str,          # 编号分步操作（1. … 2. …）
    "expected": str,       # 预期结果
}
```

**分类命名规则：**

- 分类名用源表中的**具体类别名**（该功能所在区块或合并单元格标注的菜单名），**禁止**留泛称"各菜单功能测试"。
- 有"面板基本功能""独立功能"区块的变体沿用该区块名作分类。
- 跨区块的功能描述综合项 → "功能描述综合测试"。

**步骤书写规则：**

- 编号分步：`"1. xxx\n2. yyy\n3. zzz"`。
- 每步具体到测试员**无需再解释即可执行**。
- 复用公共步骤后逐例绑定参数；“按本例”“同上”等引用必须能在该例或明确关联的定义中找到实际取值。断电、复位或上电待机后，补齐恢复到可读参数界面的操作，避免模板化步骤留下未定义条件。
- 含校验点（确认表现与描述一致）。
- 菜单导航写完整路径（如 `"进入<菜单> → <子菜单> → <功能项> → <操作>"`）。
- 源表描述若引用外部测试方法文档，能展开成步骤的展开；不能展开的在步骤中写明"按《文档名》执行"。

### 第 4 步　生成输出文件

使用同目录 `scripts/generate_testcase_sheet.py`：

```python
import sys
sys.path.insert(0, "<skill目录>/scripts")
from generate_testcase_sheet import (
    create_testcase_sheet,
    create_summary_sheet,
    add_sheet_to_source,
    save_standalone,
)
```

**输出 A —— 源文件内追加"测试用例表"子表：**

```python
saved_path, was_locked = add_sheet_to_source(source_path, test_cases, project_name)
```

`was_locked` 为 True 时告知用户：原文件被占用，已另存 `-含测试用例` 副本。

**输出 B —— 独立工作簿（默认存源文件同目录）：**

```python
out_dir = os.path.dirname(os.path.abspath(source_path))  # 或用户指定的已存在目录
file_name = f"{project_name}-测试用例表-{datetime.now():%Y%m%d}.xlsx"
path = save_standalone(out_dir, file_name, test_cases, summary_data, project_name)
```

**输出文件名与保存目录未明确时，落盘前确认；用户已指定或已认可本次默认双输出方式时直接执行。** 实跑评估使用源表副本，不修改历史正式测试表。

### 第 5 步　汇报结果

1. 分类统计表（每类多少条用例）
2. 用例总数
3. 两个输出文件路径
4. 有锁定回退时说明路径变化

## 硬性规则

- **绝不编造测试内容**：所有测试项必须来自源表实际单元格值。
- **绝不跳过数据检查**：先逐格实读再提取，杜绝按猜测的版式抽取。
- **分类必须具体**：菜单用例的分类必须是具体菜单名，不留泛称。
- **输出位置收敛**：只写用户指定的已存在目录或源文件所在目录，不写桌面等环境相关位置、不自建目录。
- **锁定文件优雅处理**：源表被其他程序占用时自动回退 `-含测试用例` 副本。
- **按分类着色**：脚本按测试分类施加不同底色（含"菜单"字样的分类统一一色，其余预设分类各有专色），不要覆盖此行为。
- **H 列（测试结果）与 I 列（备注）留空**：由测试员实测时填写。
