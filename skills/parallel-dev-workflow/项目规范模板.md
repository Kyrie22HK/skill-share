# 并行开发工作流（worktree + 资源锁）

> 建立于 <日期>。解决的问题：<几块板 / 几台测试机 / 打包机>，多个功能同时开发时，编码与编译可以并行，上板 / 装机必须排队，且谁也不能把硬件留在非基线状态给下一个人。
> 工具：`tools/wt.sh`（功能线管家）、`tools/lock.sh`（资源锁）、`tools/wt_auto.sh`（按目录识别当前线，被其余工具 source）、`tools/wt.conf`（项目配置）。

## 一、形态

```
<外层根>/
├── <仓库A>/               集成线的 <仓库A>（基线分支 <main>）：只做合并、回归、刷板
├── <仓库B>/               集成线的 <仓库B>（基线分支 <product>）
├── wt/<线名>/             功能线：.wt.env + 各仓库 worktree（分支 feat/<线名>）+ build_out/
├── .locks/                资源锁
└── _ai_workspace/<项目>/
    ├── wt/<线名>.md         状态卡；收线后移到 wt/_done/
    └── current_task.md      总账：只留各线一行索引 + 集成线自己的事
```

| 层 | 谁 | 做什么 | 不做什么 |
|---|---|---|---|
| 调度 | 用户 | 开线 / 收线、定优先级、定谁先拿硬件 | — |
| 功能线 | 每线一个会话 | 编码、编译、模拟器 / 静态验证；就差上板时拿锁 → 验 → 回基线 → 放锁；维护状态卡 | 不改总账 / 进度 / 决策日志；不碰别的线声明的文件；子代理不碰硬件 |
| 集成线 | 主目录的会话 | 合并 `feat/*`、跑 <冒烟脚本>、刷板、更新总账、出报告 | 不在主目录做功能开发 |

## 二、一条线的生命周期

```
开线：tools/wt.sh new <线名> [--repos <短名,短名>] "<一句话目标>" → 补全状态卡 → 新开会话说「启动线 <线名>」
起手：tools/wt.sh start <线名> → cd <外层根>/wt/<线名>/ → 复述理解 → 动手
硬件：lock.sh take <res> "<用途>" [--wait] → 投板 / 装机 / 验
离开：预估下次要用还要多久——空档 ≥ 阈值：回基线 → lock.sh release <res>；否则 lock.sh hold <res> --next <N>m "<原因>"
收尾：覆盖式更新状态卡；证据卷完善；提交到 feat/<线名>（用户授权）；lock.sh release --all
集成：合并 → <冒烟脚本> → 刷板 → 更新总账 → tools/wt.sh rm <线名>
```

- 起手只读状态卡与平台知识，**不读也不改总账**。
- **证据卷必须完善**：真机 / 板端验证的证据落 `test/<线名>_<日期>/`，`README.md` 写清验的什么、判据、结果、用的固件 / 基座版本；状态卡「合并前清单」列出路径。功能线不出报告，证据不全的线合并时退回补齐。

## 三、资源锁

| 资源 | 对应 | 闲置阈值 | 哪些工具会拦 |
|---|---|---|---|
| `<board-a>` | 主板 `<IP>` | 10 分钟 | <部署 / 烧录 / 冒烟全查 / 板上写文件> |
| `<phone-android>` | 安卓测试机 | 20 分钟 | <装机 / 场景驱动> |
| `<phone-ios>` | iOS 测试机 | 20 分钟 | <装机 / 推包 / 场景驱动> |
| `<mac>` | Mac 打包机 / 模拟器 | 10 分钟 | <打包工具自动拿放；模拟器一组命令手动 take> |

- 锁是租约（缺省 30 分钟）；工具经 `need_lock` 放行时自动续租。过期只标红、不自动抢：先问持有线，确认后才 `take --force`。
- 离开硬件时预估空档：≥ 阈值回基线放锁；否则 `hold --next` 登记，`status` 显示「闲置·预计 N 分钟后再用」。空档到了阈值 `hold` 会拒绝，确有理由加 `--long` 并写清。
- `take --wait` 先来先得；不带 `--wait` 遇到有人排队也会失败，不插队。
- `lock.sh run <res,res> "<用途>" -- <命令>`：单条命令的拿放快路径。
- 应急越过：`LOCK_BYPASS=1`（会打提醒）。

## 四、硬件归还基线（最容易出事故的一条）

放板锁前必须：
1. 板上运行的是 <主线 HEAD 整包 / 对账 0 差异>；本线直投过的东西要么已合并刷回，要么撤掉。
2. <设备密码 / 配置回默认；持久状态变化写进状态卡「硬件记录」>。

放手机锁前：卸掉本线装的调试包或装回主线包；**清掉本线（以及历史遗留）的设备绑定**——锁拦不住手机自己回连；状态卡记一笔。

## 五、减少合并冲突的规则

1. **共享改动单线制**：同一时刻只有一条线能改 <共享件清单：启动脚本、公共头、协议文档、产品定义…>，开线时在状态卡「只改 / 不改」里声明。
2. 两条线要碰同一个文件的，后开的线先看前一条线的状态卡，能等就等对方先合；合并时后合的线按语义融合。
3. 多语种文案等高频冲突文件：各线只追加键、不重排，键名带功能前缀。
4. 提交信息写明线名前缀，集成时好认。

## 六、子代理 / Agent teams / Workflow

- 功能线内子代理：调研、读文档、长编译时并行写别的；不碰硬件，结论回主会话核验。
- Agent teams：只用于同质、独立、验收明确、不碰硬件的一批小任务。
- Workflow：提交前多维度审查；不用于探索型开发。
- 主形态始终是一线一会话一 worktree。

## 七、成本与已知限制

- <大依赖目录> 用硬链接树拷一份（秒级、不占双倍空间）；<首次构建耗时>。
