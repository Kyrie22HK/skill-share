# CLAUDE.md 段落模板：「启动线」分支与集成线职责

> 用法：搭建第 4 步，把下面整段插进项目 CLAUDE.md 的启动协议之后，`<…>` 处按项目填写（路径相对项目约定的根）。
> 作用：用户在新会话里说「启动线 <线名>」时，会话按功能线起手，而不是走集成线的总账流程。

---

### 多线分支：用户说「启动线 <线名>」时（规范 `<docs/并行开发工作流.md>`）

本会话就是那条**功能线**，不是集成线。启动协议的「核对仓库 → 读总账 → 复述」几步替换为：
1. 跑 `<_ai_workspace/项目/tools>/wt.sh start <线名>`，读简报与状态卡 `<_ai_workspace/项目/wt>/<线名>.md`（**不读总账 `current_task.md`**，那是集成线的）
2. `cd <外层根>/wt/<线名>/`（Bash 工作目录在会话内持久，此后 <构建 / 部署 / 冒烟 / 装机> 工具自动按本线目录与端口跑）
3. 复述状态卡里的「现在做到哪 / 下一步」，得到确认再动手
4. 动硬件前 `lock.sh take <res> "<用途>"`（被占就 `--wait` 排队，先来先得）；**每次离开硬件时预估下次要用还要多久**：空档 ≥ 阈值（<板 10 分钟 / 手机 20 分钟>）就回基线放锁（规范第四节），否则 `lock.sh hold <res> --next <N>m "<原因>"`；别人的锁过期不等于不用，先发消息问再 `--force`；只改状态卡里声明的文件
5. 收尾：覆盖式更新状态卡 + 证据卷 + `lock.sh release --all`；**不改**总账 / 进度 / 决策日志（集成线合并时统一登记）；平台经验照旧写共享笔记

主目录（`<仓库A>`、`<仓库B>`）的会话是**集成线**：合并 `feat/*`、跑冒烟、刷板、更新总账、`wt.sh rm`。`wt.sh list` / `lock.sh status` 随时看全局。
