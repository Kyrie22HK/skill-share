# 并行开发工作流（一轮任务：集成线 + 功能线 + 设备锁）

> 沉淀自一个嵌入式摄像头项目的首轮实跑（2026-09-30 ~ 10-08，四条功能线；一台主板、一台安卓机、一台 iPhone、一台 Mac 打包机）。
> 核心判断：**瓶颈在设备不在脑力**——编码、编译、模拟器验证可以并行，上板 / 装机必须排队；项目知识是厚上下文型的，一条线从头到尾一个会话攒着最省。

## 零、一次调用＝一轮任务

```
收集输入（功能、设备、仓库；缺的问）→ 研判开线、给用户确认
→ pdw.sh init 建集成线 → device add 登记设备 → line new 开线 → 用户为每条线新开会话说「启动线 X」
→ 开发中：加线 line new / 加设备 device add / 下线设备 device rm / 放弃线 line rm --force
→ 逐线合并 → line rm → 全部收完 → 复盘 → pdw.sh close（归档、清锁、清线目录）→ 本轮结束
```

脚本在本 skill 的 `scripts/`。`init` 把它们拷进 `<根>/.pdw/bin/`，此后所有会话都用 `<根>/.pdw/bin/pdw.sh` 与 `lock.sh`（一轮一份，互不影响）。本轮的全部状态都在 `<根>/.pdw/`：配置 `conf.sh`、集成线任务卡 `task.md`、设备登记 `devices/`、锁 `locks/`、线状态卡 `cards/`。功能线目录在 `<根>/wt/<线名>/`。关闭一轮时归档到 `<根>/.pdw-archive/`，项目有自己的工作区 / 文档目录时用 `init --archive` 指过去。不改项目自己的文件（CLAUDE.md、.gitignore 等）；根目录在 git 仓库里时只写该仓库的本地忽略 `info/exclude`。

**本会话被「启动线 X」触发时**，你是功能线，直接跳到第四节。

## 一、收集输入（缺什么问什么）

先从用户的话和代码库里取，取不到的用问答补齐（一次最多问 4 题，每题给推荐默认值；能自己查到的不问）：

| 要什么 | 每项要的信息 | 用户没给时 |
|---|---|---|
| **功能清单** | 名字、一句话目标（保留用户原话）、涉及哪些仓库、会碰哪些文件 / 模块、验收判据、要用哪些设备 | 问：这轮要并行做哪些功能？各自做完的样子是什么？ |
| **设备清单** | 设备名（小写连字符，如 `board-a`、`phone-android`）、说明、IP（板子）、**闲置上限**（分钟）、**归还基线**（放锁前要回到的状态） | 问：手上有哪些设备可用？各自怎么回到干净状态？闲置上限按归还成本给推荐：板子回基线约 1 分钟→10；手机要卸包清绑定→20；无归还成本的工具→5 |
| **仓库与基线分支** | 每个仓库的路径与基线分支；根目录（放 `.pdw/` 与 `wt/` 的地方，一般是装着各仓库的外层目录） | 从当前目录探测，向用户确认 |
| 可选 | 各线需要错开的端口、线环境变量、要硬链接共享的大目录（如 `node_modules`）；归档目录（项目有协作工作区 / 文档目录时，本轮记录归到那里） | 从项目工具与目录约定里找；没有就不配 |

## 二、研判开线，给用户确认

不是功能一多就开线：

| 情形 | 做法 |
|---|---|
| ≥ 2 个相互独立的功能，编码可并行、设备稀缺 | 开线 |
| 几个功能改同一批文件（冲突成本 > 并行收益） | 串行，或后开的线等前一条合并 |
| 同质、独立、验收明确、不碰设备的一批小活 | 不开线：某条线的会话临时起子代理 / Agent teams |
| 单个功能 | 不开线，不走本流程 |

把方案列给用户确认：线名、目标、仓库、交叠文件与合并顺序（**改同一判定段的线，后合的一方负责语义融合**）、设备与阈值、基线。

## 三、建任务（集成线）

在根目录执行：

```
<skill>/scripts/pdw.sh init <任务名> --repo <短名>=<路径>[@<基线分支>] … [--port VAR=基数[:步长]] [--env 'K=模板'] [--hardlink 短名:相对路径] [--archive <归档目录>]
.pdw/bin/pdw.sh device add <设备> --idle <分钟> --desc "…" [--ip <IP>] --baseline "<放锁前要回到的状态>"
.pdw/bin/pdw.sh line new <线名> [--repos a,b] "<一句话目标>"
```

然后：
1. 补全 `.pdw/task.md`（用户原话、功能清单与研判、合并顺序与冲突预判）和每张 `.pdw/cards/<线名>.md`（用户原话、只改 / 不改、验收判据、要用的设备）——状态卡是新会话唯一的上下文，写到「只看它就能开工」。
2. 项目里有动设备的脚本时，**可选接入**：在改设备的分支前加 `[ -f "<根>/.pdw/bin/pdw_env.sh" ] && source "<根>/.pdw/bin/pdw_env.sh" && need_lock <设备>`（板子可用 `need_lock "$(board_res_of_ip "$IP")"`）。接入后无锁会被拒、有锁自动续租；不接入时锁靠会话自觉遵守。改项目脚本前先问用户。
3. 开线后先在一条线的 worktree 里把项目常用工具的只读子命令跑一遍：主目录有产物、worktree 没有的差异会让工具露出隐藏假设。
4. 告诉用户：每条线新开一个 Claude Code 会话（在根目录或其子目录启动），说「启动线 <线名>」。

## 四、功能线会话（「启动线 X」）

1. `<根>/.pdw/bin/pdw.sh line start X`：读简报与状态卡；`cd <根>/wt/X`（此后工具按目录自动识别本线，变量与端口都是本线的）。
2. 复述「做到哪 / 下一步」，得到确认再动手。不读也不改 `task.md`。
3. **用锁**：
   - 动设备前 `lock.sh take <设备> "<用途>"`；被占就 `--wait` 排队（先来先得）。拿锁时会提示该设备的归还基线。
   - 锁命令一律在 `<根>/wt/<线名>/` 里跑：在根目录跑会被认成集成线 main，`release --all` 会放掉集成线的锁。
   - 设备可以登记成「只读共用、改动独占」：只读使用（看状态、连上去用）不拿锁、多线同时用，改动设备状态才 `take`，并先告知其他线。
   - **每次离开设备时预估下次要用还要多久**：空档 ≥ 阈值就回基线放锁；没一会就要用的 `lock.sh hold <设备> --next <N>m "<回来要做什么>"`。
   - 别人的锁过期**不等于不用**：先发消息问持有线，确认后才 `take --force`。
   - 锁只拦得住工具、拦不住设备自己的行为（如手机里旧绑定自动回连已交出的设备）：放锁前连设备侧状态一起回基线。
4. 线之间能互发消息时，直接约设备交接、通报新占用的文件；集成线只在冲突时调度。
5. 收尾：覆盖式更新状态卡（做到哪 / 卡点 / 下一步 / 设备记录 / 证据路径）；证据写清验的什么、判据、结果、用的版本；`lock.sh release --all`；提交到 `feat/X`（按用户授权）；通知集成线合并。功能线不出报告。

## 五、集成线运转

- **合并**：
  - 状态卡「只改」对照 `git diff --stat`，范围外改动要线说明理由。
  - 能快进就快进；有冲突时读双方状态卡与提交说明，**按语义逐处融合**，不是机械取并集。
  - 合并后编译所有构建形态。快进合入的就是线里验过的提交，不重复验；rebase 过或解过冲突的，按项目冒烟与关键场景复验后再推送。
- **收线**：`pdw.sh line rm <线名>`（未提交、未合并、还持锁的会被拒；放弃的线 `--force`）。合并时把共享文档里被这条线弄过时的地方一并改掉，通知在跑的线基线前进了。收线或关闭一轮后提醒用户在 IDE 里重载窗口（VSCode 会把线工作树当仓库自动打开，目录删了也不会自己关）。
- **尾段线**：只剩「同步主线 + 复验」的线，集成线直接 rebase、合并、一次复验后收线，不必再占线会话。
- **运行中变更**：
  - 加线：`line new`。
  - 加设备：`device add`（同名再 add 即更新阈值与基线）。
  - 下线设备：`device rm`（被持锁或有人排队会被拒）。
  - 每次变更都会自动记进 `task.md` 的事件。
- **全局视图**：`pdw.sh status`（设备与锁、各线分支状态、集成线各仓库状态、收线进度）。

## 六、收口：关闭集成线

1. 所有线都已 `line rm`（`pdw.sh status` 显示在跑 0 条）。
2. 复盘：把本轮摩擦与对策写进 `task.md`「摩擦与经验」；项目有报告规范的，按需出汇总报告（素材＝`task.md` + 各线状态卡与证据）。新摩擦值得长期保留的，提议补进本 skill 的 [实跑经验.md](实跑经验.md)。
3. `pdw.sh close`：还有线没收、还有别的身份持锁就拒绝；通过后把任务卡、线状态卡、设备登记归档到 `<归档目录>/<时间>_<任务名>/`（归档目录缺省 `<根>/.pdw-archive`），清掉 `.pdw/` 与空的 `wt/`；各仓库的 `feat/*` 分支保留。
4. 告诉用户本轮已结束；下一轮并行开发重新调用本 skill。

## 七、子代理 / Agent teams / Workflow 放在哪

- 功能线内子代理：大范围调研、并行读文档、长编译时同时写别的、实验数据分析；**不碰设备**，结论回主会话核验。
- Agent teams：只用于同质、独立、验收明确、不碰设备的一批小任务，由那条线临时起、起完自己验一遍。
- Workflow：提交前多维度审查一类确定性流水线；不用于探索型开发。

## 八、附属文件

- `scripts/pdw.sh`（任务 / 设备 / 线）、`scripts/lock.sh`（设备锁）、`scripts/pdw_env.sh`（公共头：找任务、识别当前线、`need_lock`）：头注即用法。
- `scripts/selftest.sh`：临时目录里跑完整一轮（57 项，约 40 秒），改了脚本后必跑。
- [实跑经验.md](实跑经验.md)：建任务前读一遍；每轮收口时对照增补。
