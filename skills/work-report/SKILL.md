# 双版工作报告规格（Claude / Codex 共用）

> 来源：rv1126 雷视融合项目多份报告的迭代定稿要求（2026-07-10 整理，2026-07-14 通用化至用户级）。
> **配套脚本（本 skill `scripts/` 目录）**：`shell_template.html`（规格壳模板，含占位符 TITLE/TOCTITLE/TOC/CONTENT，CSS/JS 全内联）+ `assemble.py`（内容片段→成品 html 组装，片段格式见脚本头注释）+ `embed_video.py`（录屏 / 演示视频 → 可内嵌的视频片段，见第二节 3b）+ `selfcheck.py` / `quality_check.py`（第七节结构及共享壳检查）+ `browser_check.py`（已有本地 Chrome 的真实交互、截图和视频实跑；也可用当前浏览器工具）。出新报告一律走这条流水线，保证壳体跨报告逐字节一致；壳模板即视觉/交互规格的权威实现。
> 同源 skill：`project-tour`（项目导览版——给新接手者建立认知的深度导览；与本 skill 共享壳流水线与质量规则，差异在内容结构与"报告即门户"约定）。
> 从当前加载的 SKILL.md 的真实路径定位 `scripts/`（软链先解析），不要从项目 cwd 猜路径。Claude 的同名项目级遮蔽规则不推广到 Codex；有项目特化规格时先明确其适用范围，避免选错旧副本。

## 执行入口与质量基准

首次在一个项目出稿，先读 [排版与实跑验收.md](排版与实跑验收.md)，选择该项目一份质量认可、主题相近的既有 HTML，实际打开并截取首页与代表性正文；没有项目样本时按该文档的组件范式。记录参考路径、适用主题和本次有意保留的阅读方式，不复制旧结论或项目事实。

两版同源指**事实、数字、限定条件和结论一致**，不是把 Markdown 逐行转成 HTML。先完成内容母本，再按概要、因果说明、证据对照、边界、交付等阅读任务安排组件；使用现成类名和壳，保留长文各章的证据密度。不要因换成 Codex 而换主题、缩成提纲或省略图示。

开始前核：资料是否齐全、输出目录、脚本真实路径、Python、浏览器（以及视频所需 ffmpeg）。当前会话有浏览器工具就使用；也可用已有本地 Chrome。缺工具时保留内容与结构检查进展，明确视觉/交互待验，不能用 selfcheck PASS 宣称质量已全部达标。目录和任务已明确授权时直接生成，不重复询问。

## 一、定位与产物

- **双版**：`.md`（内容母本，工作区可 grep/diff）+ `.html`（阅读版，**单文件自包含**，CSS/JS/SVG 全内联，双击即开）。两版内容同步，md 先行、html 排版。
- 存放位置遵循项目既有约定：有 `_ai_workspace` 协作框架的项目放 `_ai_workspace/<项目>/report/<域>/`（如 `report/radar/`）；无约定则与用户确认。文件名用**描述性中文名**，不用 index；沿用既有命名连续性（已发布的文件名不改，防引用断链）。
- **报告即门户**（适用于有 `_ai_workspace` 框架的项目）：报告出稿后，`current_task.md` 里对应任务块只留一行索引指向报告，细节不再重复维护。

## 二、内容结构（认知弧线，非流水账）

1. **概要先行**：KPI 数字卡/表格 + 一句话结论卡 + 迭代/阶段时间线。读者 30 秒拿到全部结论。
2. **过程章节**：按"现象 → 归因（带数据实证）→ 修复 → 验证"的因果链组织，不按时间流水；每个归因给出**证据数字与口径**（n=、med/p90、归档路径），每个修复给出**回归/验证结果**。
3. **视觉证据内嵌**：证据本身是视觉性的（画质对比、截图类）时，截图必须**内嵌进报告本体做并排对比**，不得只留归档目录路径。三要点：① **体积控制**——html 版 base64 内嵌 JPEG，降采样至 ~880px 宽、quality 85；② **画质类证据的关键对比另配 1:1 原分辨率裁切**（降采样会抹掉块效应等细节，1:1 裁切保真）；③ **归档注明**——图墙下注明"内嵌图为降采样预览，原始无损 PNG 见归档目录"。**HTML 版是单文件自包含的交付件**（图 base64、SVG 内联、视频数据块），单发即完整；**md 版不嵌图**：原图处写一行文字说明「（图 N 见 HTML 版）」，表格里纯图片的行去掉、保留说明行。**报告目录下不建附件文件夹**，裁切图、SVG、转码片段等原件放进对应的证据归档目录（如 `<证据卷>/报告附件/`），报告正文提到时指向那里。
   3b. **视频演示（必要时）**：证据是**动态过程**、截图说不清时才用视频——转场 / 闪屏 / 动画、时序与节奏、跟随与实时性（如画框跟着目标走）、操作到结果的完整一段。静态结果仍用截图，不要用视频代替截图。做法：
   - 用 `scripts/embed_video.py <输入> <输出前缀> --caption "视频 N　…" [--ss --t --speed --box --crf]` 转码：H.264 / yuv420p / faststart / 无音轨，只截关键几秒（一般 5–15 s），长边 ≤ 960，界面一闪而过的动画可 `--speed 0.5` 放慢并在图注写明。产物 `<前缀>.frag.html` 原样粘进内容片段（figure.video + 视频数据块），壳脚本在视频接近视口时把数据块转成 Blob 地址播放（大段 `data:` URI 视频在 Safari 上不稳，不要手写 `src="data:…"`）。
   - 体积：单段 ≤ 2 MB 为宜（> 4 MB 工具与自检都拦），整份报告视频合计 ≤ 8 MB 为宜（> 16 MB 自检报错）。超了就缩短、调大 `--crf`、降 `--box` / `--fps`。
   - 改前 / 改后对照用两列网格并排（同截图墙写法），每段一个 figcaption 写清看什么、在哪一秒。录屏的特殊情况写进图注（如「按手机竖向坐标录制，横屏段画面侧转」）。
   - md 版：不放视频也不引封面，写一行「▶ 视频 N…（视频见 HTML 版）」；`embed_video.py` 的输出前缀指到证据归档目录（如 `<证据卷>/报告附件/v1_…`），转码片段、封面、frag 都留在那里，不落报告目录。
   - **交付前真放一遍**：自检只查结构，能不能播要在浏览器里看。浏览器窗口在后台时 Chrome 会推迟媒体加载；可用无头 Chrome 验：页面解析完就给每个视频挂 `loadeddata` 记录 `readyState` / `videoWidth` / 播放进度，再挂一个延迟数秒才返回的资源拖住 load 事件，`--dump-dom` 读结果（`--virtual-time-budget` 下媒体管线不推进，不能用）。
4. **已知边界诚实声明**：失败的路线、修复的代价、残留问题、物理边界，全部写明——诚实优于漂亮。
5. **方案/讨论稿章节**（如有）：选项对照表 + 推荐 + 待拍板标注，不替用户做决定。
6. **验收/收口**：指标表 + 判定 + 交付物清单（commit 哈希、部署版本、工具、归档目录）。
7. **经验沉淀**：编号条目，每条一句加粗论点 + 一句展开，可被未来直接引用。
8. **附录·术语速查**：表格，本项目语境释义、每条一两行，供无项目上下文读者阅读。

## 三、文风（硬约束）

- **平实直叙技术事实**。禁比喻金句、禁营销腔、禁抒情（苹果官网风被否过）。
- **禁项目内部代号与戏剧化词**（"真凶""战役N"等）于标题与正式措辞；正文引用既有文档名时可保留原名。
- 数字必须带来源口径；推断与实证分开表述；用户的输入/拍板记录为"用户确认/用户拍板"并标日期。

## 四、HTML 视觉规格（沿用既有暖色书卷风）

- 配色 tokens：底 `#f6f1e7`、卡片 `#fffdf8`、文字 `#2c2a26`、赤陶 `#b8502c`/`#c9714e`、细线 `#e3dccc`、好 `#3f7d54`、坏 `#b03a2e`、警 `#b8862c`、深暖代码块 `#2c2a26`。
- 字体：**衬线标题**（Georgia/"Songti SC"），正文系统无衬线；正文 ~17.5px、行高 ~1.82；h1≈39/h2≈27/h3≈21。
- 布局：内容区 `max-width:1280px` 居中 + 左侧 ~272px 实体目录栏（`@media(min-width:1341px)` 给 body 留 padding；窄屏侧栏隐藏复位）。避免 960 窄报告感与 1600+ 满屏两个极端。
- 组件库（制造视觉节奏的手段，不靠文案煽情）：KPI 数字卡、结论卡变体（verdict/ok/warnc/lesson/note 左色条）、阶段时间线 `.phase`、对照表、pill 标签 `.tag`、事实芯片 `.chips`、`<details>` 折叠、内联 SVG 流程图、内嵌视频 `figure.video`（由 `embed_video.py` 生成，见第二节 3b）。
- 以上全部由 `scripts/shell_template.html` 提供，不要手写壳。
- **截图对比墙**（第二节"视觉证据内嵌"的排版实现）：使用壳内 `<div class="image-grid">` + `<figure>` + figcaption，桌面两列、手机一列。旧报告内联两列结构可继续读取，新稿使用响应式组件；截图 `<img>` 由壳 JS 自动接入灯箱（点击放大），作者无需写任何附加结构或类名。

## 五、必备交互

- 左侧固定目录 `side-toc` + **scroll-spy** 高亮（嵌套：部分标签 `.pt` + 小节链接）。
- 顶部滚动进度条 `#prog` + 回到顶部按钮。
- 每张 SVG 图与每张截图 `<img>` **点击 → 暗色灯箱**（滚轮缩放 + ＋/−/⟳/✕ 按钮 + Esc/点空白关闭）。SVG 侧灯箱只绑定 `figure.diagram .scroll`——内容片段里每张图必须按 `figure.diagram > div.scroll > svg` + figcaption 结构写，缺 `.scroll` 层则点击放大/悬浮提示/宽图横向滚动全失效。img 侧由壳 JS 自动包裹接入（链接内 img 除外），作者无需写结构。
- 以上 CSS/JS 由壳模板自带，经 `assemble.py` 组装获得，保持跨报告一致性。

## 六、SVG 流程图规则

- 低饱和配色：灰 `#A8A493`、青石 `#5E7287`、橄榄 `#6B7A4F`、赤陶 `#C2562F`、坏 `#B03A2E`、好 `#3F7D54`。
- 图的选题优先级：失效链/因果链 > 数据流 > 概念映射；每图配 figcaption（编号+一句话说明）。
- **框内文字必须放得进框**：逐个 `<text>` 估宽（中文 ≈ 字号 px/字、拉丁/数字 ≈ 0.55×字号、`text-anchor="middle"` 两侧各留 ≥6px）；放不下就加宽框/缩字号/精简文案。
- SVG 文本内 `&`/`<` 转义为 `&amp;`/`&lt;`（`<script>` 里的 `&&` 不转义）。

## 七、交付前自检（必须执行并向用户复述结果）

用 `scripts/selfcheck.py --profile report <report.html>` 核验结构与壳；再按 [排版与实跑验收.md](排版与实跑验收.md) 做真实浏览器和人工质量对照。结构检查不替代目测：

1. 标签配平：`svg/table/details/pre/figure/div/h2/h3/tr/td/th/ul/ol/li` 起止数量一致；
2. TOC↔id：每个侧栏锚点在正文有对应 `id`；**id 不得数字开头**（scroll-spy 会整体崩掉连带灯箱失效）；
3. SVG 文本溢出全量估算为零；
4. 无 TODO/FIXME/`{{}}` 占位符；SVG 无裸 `&`；
5. 长无空格标识符（路径/宏）所在 `code` 有 `overflow-wrap:break-word`；
6. figure.diagram 结构：内含 svg 必须由 `<div class="scroll">` 包裹（灯箱 JS 只绑定 `figure.diagram .scroll`，缺层则灯箱/悬浮提示/横滚容器全失效）。
7. 内嵌视频：每个视频有封面、`data-src` 指向存在的数据块、不用 `src="data:"`；figure.video 有 figcaption；单段 ≤ 4 MB、合计 > 8 MB 警告 / > 16 MB 报错；壳含视频接入脚本。自检之外，视频须按第二节 3b 在浏览器里真放一遍。

## 八、收尾动作

- 文末 footer：基于分支/commit、部署版本、数据归档路径、"随代码演进可能滞后"。
- 交付时复述：**章节结构 + 自检/浏览器/视觉审读结果 + 参考样本与差异 + 未验事项**。保存截图和检查日志到证据目录；用户反馈后继续迭代。
- 有 `_ai_workspace` 协作框架的项目：按收尾协议更新 `current_task.md`（报告即门户索引）与 `progress.md`（条目注日期）。
