# 双版工作报告规格（用户级通用版）

> 来源：rv1126 雷视融合项目多份报告的迭代定稿要求（2026-07-10 整理，2026-07-14 通用化至用户级）。
> **配套脚本（本 skill `scripts/` 目录）**：`shell_template.html`（规格壳模板，含占位符 TITLE/TOCTITLE/TOC/CONTENT，CSS/JS 全内联）+ `assemble.py`（内容片段→成品 html 组装，片段格式见脚本头注释）+ `selfcheck.py`（第七节自检清单的脚本化实现，逐份跑、输出 PASS/FAIL）。出新报告一律走这条流水线，保证壳体跨报告逐字节一致；壳模板即视觉/交互规格的权威实现。
> 同源 skill：`project-tour`（项目导览版——给新接手者建立认知的深度导览；与本 skill 共享壳流水线与质量规则，差异在内容结构与"报告即门户"约定）。
> 若当前项目的 `.claude/skills/` 下有同名项目级 skill，以项目级为准（可能含项目特化路径与既有报告参考实现）。

## 一、定位与产物

- **双版**：`.md`（内容母本，工作区可 grep/diff）+ `.html`（阅读版，**单文件自包含**，CSS/JS/SVG 全内联，双击即开）。两版内容同步，md 先行、html 排版。
- 存放位置遵循项目既有约定：有 `_ai_workspace` 协作框架的项目放 `_ai_workspace/<项目>/report/<域>/`（如 `report/radar/`）；无约定则与用户确认。文件名用**描述性中文名**，不用 index；沿用既有命名连续性（已发布的文件名不改，防引用断链）。
- **报告即门户**（适用于有 `_ai_workspace` 框架的项目）：报告出稿后，`current_task.md` 里对应任务块只留一行索引指向报告，细节不再重复维护。

## 二、内容结构（认知弧线，非流水账）

1. **概要先行**：KPI 数字卡/表格 + 一句话结论卡 + 迭代/阶段时间线。读者 30 秒拿到全部结论。
2. **过程章节**：按"现象 → 归因（带数据实证）→ 修复 → 验证"的因果链组织，不按时间流水；每个归因给出**证据数字与口径**（n=、med/p90、归档路径），每个修复给出**回归/验证结果**。
3. **视觉证据内嵌**：证据本身是视觉性的（画质对比、截图类）时，截图必须**内嵌进报告本体做并排对比**，不得只留归档目录路径。三要点：① **体积控制**——html 版 base64 内嵌 JPEG，降采样至 ~880px 宽、quality 85；② **画质类证据的关键对比另配 1:1 原分辨率裁切**（降采样会抹掉块效应等细节，1:1 裁切保真）；③ **归档注明**——图墙下注明"内嵌图为降采样预览，原始无损 PNG 见归档目录"。md 版用相对路径引图（编辑器可直接预览）。
4. **已知边界诚实声明**：失败的路线、修复的代价、残留问题、物理边界，全部写明——诚实优于漂亮。
5. **方案/讨论稿章节**（如有）：选项对照表 + 推荐 + 待拍板标注，不替用户做决定。
6. **验收/收口**：指标表 + 判定 + 交付物清单（commit 哈希、部署版本、工具、归档目录）。
7. **经验沉淀**：编号条目，每条一句加粗论点 + 一句展开，可被未来直接引用。
8. **附录·术语速查**：表格，本项目语境释义、每条一两行，供无项目上下文读者阅读。

## 三、文风（硬约束）

- **平实直叙技术事实**。禁比喻金句、禁营销腔、禁抒情（苹果官网风被否过）。
- **禁项目内部代号与戏剧化词**（"真凶""战役N"等）于标题与正式措辞；正文引用既有文档名时可保留原名。
- 数字必须带来源口径；推断与实证分开表述；用户的输入/拍板记录为"用户确认/用户拍板"并标日期。

## 四、HTML 视觉规格（Claude 暖色书卷风）

- 配色 tokens：底 `#f6f1e7`、卡片 `#fffdf8`、文字 `#2c2a26`、赤陶 `#b8502c`/`#c9714e`、细线 `#e3dccc`、好 `#3f7d54`、坏 `#b03a2e`、警 `#b8862c`、深暖代码块 `#2c2a26`。
- 字体：**衬线标题**（Georgia/"Songti SC"），正文系统无衬线；正文 ~17.5px、行高 ~1.82；h1≈39/h2≈27/h3≈21。
- 布局：内容区 `max-width:1280px` 居中 + 左侧 ~272px 实体目录栏（`@media(min-width:1341px)` 给 body 留 padding；窄屏侧栏隐藏复位）。避免 960 窄报告感与 1600+ 满屏两个极端。
- 组件库（制造视觉节奏的手段，不靠文案煽情）：KPI 数字卡、结论卡变体（verdict/ok/warnc/lesson/note 左色条）、阶段时间线 `.phase`、对照表、pill 标签 `.tag`、事实芯片 `.chips`、`<details>` 折叠、内联 SVG 流程图。
- 以上全部由 `scripts/shell_template.html` 提供，不要手写壳。
- **截图对比墙**（第二节"视觉证据内嵌"的排版实现，壳模板外唯一例外，用内联样式）：两列网格 `<div style="display:grid;grid-template-columns:repeat(2,minmax(0,1fr));gap:16px">` + `<figure style="margin:0">` + 小字 figcaption，无需改壳模板；灯箱只绑 SVG（`figure.diagram .scroll`），img 不参与灯箱，属预期行为。

## 五、必备交互

- 左侧固定目录 `side-toc` + **scroll-spy** 高亮（嵌套：部分标签 `.pt` + 小节链接）。
- 顶部滚动进度条 `#prog` + 回到顶部按钮。
- 每张 SVG 图**点击 → 暗色灯箱**（滚轮缩放 + ＋/−/⟳/✕ 按钮 + Esc/点空白关闭）。灯箱 JS 只绑定 `figure.diagram .scroll`——内容片段里每张图必须按 `figure.diagram > div.scroll > svg` + figcaption 结构写，缺 `.scroll` 层则点击放大/悬浮提示/宽图横向滚动全失效。
- 以上 CSS/JS 由壳模板自带，经 `assemble.py` 组装获得，保持跨报告一致性。

## 六、SVG 流程图规则

- 低饱和配色：灰 `#A8A493`、青石 `#5E7287`、橄榄 `#6B7A4F`、赤陶 `#C2562F`、坏 `#B03A2E`、好 `#3F7D54`。
- 图的选题优先级：失效链/因果链 > 数据流 > 概念映射；每图配 figcaption（编号+一句话说明）。
- **框内文字必须放得进框**：逐个 `<text>` 估宽（中文 ≈ 字号 px/字、拉丁/数字 ≈ 0.55×字号、`text-anchor="middle"` 两侧各留 ≥6px）；放不下就加宽框/缩字号/精简文案。
- SVG 文本内 `&`/`<` 转义为 `&amp;`/`&lt;`（`<script>` 里的 `&&` 不转义）。

## 七、交付前自检（必须执行并向用户复述结果）

用 `scripts/selfcheck.py` 核验，不目测：

1. 标签配平：`svg/table/details/pre/figure/div/h2/h3/tr/td/th/ul/ol/li` 起止数量一致；
2. TOC↔id：每个侧栏锚点在正文有对应 `id`；**id 不得数字开头**（scroll-spy 会整体崩掉连带灯箱失效）；
3. SVG 文本溢出全量估算为零；
4. 无 TODO/FIXME/`{{}}` 占位符；SVG 无裸 `&`；
5. 长无空格标识符（路径/宏）所在 `code` 有 `overflow-wrap:break-word`；
6. figure.diagram 结构：内含 svg 必须由 `<div class="scroll">` 包裹（灯箱 JS 只绑定 `figure.diagram .scroll`，缺层则灯箱/悬浮提示/横滚容器全失效）。

## 八、收尾动作

- 文末 footer：基于分支/commit、部署版本、数据归档路径、"随代码演进可能滞后"。
- 交付后向用户复述：**章节结构 + 自检结果**，等确认再迭代。
- 有 `_ai_workspace` 协作框架的项目：按收尾协议更新 `current_task.md`（报告即门户索引）与 `progress.md`（条目注日期）。
