# 入口、记忆与能力的迁移模式

> 用途：处理外置工作区、多项目、双客户端及 Claude 隐式依赖。
> 更新：实际迁移出现新差异时修订；示例路径须替换为目标项目实测值。

## 入口选择

| 现场情况 | 适用方案 | 要验证的边界 |
| --- | --- | --- |
| 单仓库，允许规则进仓库 | 发现链中的 `AGENTS.md`，详细文档继续按需索引 | 当前启动目录是否经过该入口、是否有 override |
| 项目规则位于仓库外 | 保留外置入口；通过明确提示读取，或使用用户认可的可发现入口导航 | 子仓库启动不能假设会越过仓库根加载外层 |
| 同一外层有多个独立项目 | 每项目完整入口；用户选中一个再启动 | 不默认加载另一个项目入口/任务卡，也不依靠它补全规则 |
| 用户确实需要统一公共入口 | 共用规则与项目差异分层，入口只导航选中的项目 | 每个入口启动位置可达，公共规则不携带另一项目的实时状态 |
| 用户要求根目录不放入口 | 无根入口；项目内显式启动协议与完整规则 | 根目录无 `AGENTS.md` 及可产生入口效果的替代/覆盖文件；别为通过测试偷偷加路由 |

这些是选项，不是统一目录模板。不要为了符合某个旧工作区模板移动 `.git`、仓库或构建路径。确实需要改变目录结构时，先完成依赖分析及可审阅方案，再按授权范围处理。

自动发现需结合客户端实际机制核验。2026-10-29 核对的官方说明是：全局入口位于 Codex home；项目入口沿项目根到当前目录组合，同层优先 override，再普通入口和配置的 fallback。文件读取有容量限制。`_ai_workspace/<项目>/AGENTS.md` 若不在发现链内，需要显式读取。详见 [官方入口文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。后续迁移重新核对，不固定容量或依赖旧版本默认值。

## 项目入口骨架

以下是写作提纲，生成时替换占位值、删去不适用项。保留原项目约束的实质内容；不要交付只剩导航而缺失必要规则的入口。

```markdown
# <项目名> 项目入口

> 用途：本项目协作规则与接续入口。
> 更新：<规则维护方式与来源日期>；实时状态维护于 <任务卡>。

## 启动

用户说“<启动口令>”或显式指定本文件时：
1. 读取 <入口路径>，再读取 <任务卡路径>；启动只进入本项目。
2. 从 <命令工作目录> 核对 <仓库路径> 的真实分支、HEAD 和工作树。
3. 简报承接点、卡点与下一步。仅启动时不执行旧待办；有具体任务时继续有效授权范围内的工作。
4. 实施时按需读地图、相关决策、模块资料和源码。

## 项目边界与工程约束

<从原规则保留下来的适用范围、关键契约、构建和验证要求。>

## 授权与现场核实

<当前约定及其作用域；哪些事项已有授权、哪些需要另行确认。>
<设备、版本、旧分支和测试结论的核实方法。>

## 按需入口与能力

<地图、专题文档、证据、历史上下文、技能权威源及使用方式。>
<当前可用工具与明确的能力缺口，不抄旧客户端工具名作保证。>

## 收尾

<任务卡、进度、报告索引的更新方式与产物位置。>
<决策/架构的维护约定；归档门户和唯一原件保全方式。>
```

有完整独立入口且要求隔离时，共用的少量关键规则可以在入口内完整表达，并注明来源；不要为了消除所有重复而让启动依赖兄弟项目。较长的专题规范仍采用单一来源、按需读取。

## Claude 共存

先确认用户是否继续使用 Claude。保留原入口，或在保全原文后将 `CLAUDE.md` 改为仅导入本项目公共规则的兼容入口。使用客户端支持的导入语法前核实其行为；未验证时明确要求读取目标文件。

共存时避免双向导入、循环引用和两份独立维护的规则正文。Claude 独有 hook 等适配信息可以留在 Claude 入口；Codex 所需规则不能藏在其不可达的私有记忆里。不因用户迁移到 Codex 就删除 Claude 配置、登录数据或其他项目记忆。

## 记忆处理

| 原始内容 | 合适落点 |
| --- | --- |
| 只在私有记忆中存在、当前仍适用的项目约束 | 项目入口或专题规范，保留来源引用 |
| 活跃任务的唯一接续信息 | 任务卡；不复制同一项为多个实时状态 |
| 关键历史决策、失败经验、旧授权原话 | 冻结原文或已有归档，主题索引指向现行核实位置 |
| 已在正式文档完整保存的重复记忆 | 链接现有来源，通常不再复制 |
| 无关项目、凭据或个人资料 | 不纳入此次迁移；确需引用时保留适当访问边界 |

保存原文时建立类似下表的索引，不把整份 MEMORY 放进每次启动的必读清单：

| 要解决的问题 | 历史来源与日期 | 当前核实位置 |
| --- | --- | --- |
| 某条授权为何这样理解 | 原始反馈所在条目 | 当前用户指令与目标任务范围 |
| 某分支为何独立维护 | 对应决策或冻结记忆 | 当前分支、产品差异文档 |
| 某工具曾经踩过什么坑 | 对应实验记录 | 当前工具源码、配置及本次实测 |

冻结目录标明用途、来源、迁入日期和“不续写”。原文哈希用于证明保全；它不证明原文内容仍有效。如果敏感原件不能复制，则记录保留位置和内容缺口，不能宣称逐字节完整迁移。

## 能力映射

| Claude 依赖 | Codex 侧处理 | 验证证据 |
| --- | --- | --- |
| 私有项目记忆触发入口 | 可达的项目入口与显式启动提示 | 新会话实际读取来源及顺序 |
| `/某技能` | 查当前技能目录/列表；必要时显式读权威源 `SKILL.md` | 路径可读、发现列表、实际调用分别记录 |
| Claude 浏览器插件 | 使用当前可用浏览器/自动化工具完成同等验收 | 实际 UI 操作、payload 或画面；不能用端口通替代 |
| hooks / commands / agents | 逐项判断是否仍需要；保留意图，选当前可用机制 | 相应机制是否被执行，不能把普通脚本当作自动 hook |
| `.claude/settings*.json` | 视作旧配置来源；权限以当前运行环境为准 | 当前有效权限、可调用工具与配置来源 |
| 旧部署/测试脚本 | 检查硬编码与副作用，适配实际目标 | 读源码及适当的只读探测，写入操作另受当前授权约束 |

2026-10-29 官方技能文档列出用户级 `~/.agents/skills` 并支持技能目录软链。已有权威库时可链接单个 skill，不复制规范；先检查同名目录和配置，不能覆盖既有安装。具体客户端可能不同，实际发现结果优先。参见 [官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

适配是保留验证能力。例如原工作流要求真实浏览器或设备画面，换客户端后仍需要等价证据；工具缺失属于未验证项，不是降低验收标准的理由。全局配置调整若超出迁移任务范围，交付明确缺口与可审阅建议，不顺手修改。
