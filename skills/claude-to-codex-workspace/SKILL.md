# Claude 工作区适配 Codex

> 用途：把既有协作流程迁为 Codex 可发现、可接续、可核验的项目工作区。
> 更新：依据真实迁移和用户反馈修订；客户端机制以目标环境及当前官方文档为准。

## 迁移目标

从项目能否继续工作出发，保留四件事：规则来源可追溯、项目与授权边界清楚、任务承接信息完整、完成声明有证据。入口名和目录形态服务于这些目标。

迁移通常只调整工作区入口、导航、必要的历史上下文及能力说明。沿用项目已有目录、语言、证据规范和构建工具；不要顺带执行任务卡里的业务待办、重构仓库或改写全部项目文档。已有明确授权的工作直接推进，缺少关键目标信息时先查现有资料再澄清。

## 1. 定位目标并建立基线

先找现有 `CLAUDE.md`、`AGENTS.md` / `AGENTS.override.md`、任务卡和工作区地图。显式记录工作目录、代码仓库根、工作区路径、项目名称及有效入口来源。多项目迁移可逐个盘点；只迁一个项目时，不默认读其他项目历史。

- 先读目标入口与任务卡，再按需查决策、进度、地图、代码和 Claude 记忆索引。检查隐藏文件用 `rg --files --hidden` 并排除 `.git`、构建产物和大件证据；不递归倾倒整个主目录或 SDK。
- 对相关仓库运行 `git --no-optional-locks -C <repo> status --short --branch`、`rev-parse --show-toplevel`、`log -1`。记录原有修改；工作树不干净不等于必须清理，不自动 reset、stash 或切分支。
- 对即将替换、删减的入口保存一份可恢复原件与 SHA256。对需保全的任务内容、决策和架构登记基线；重要未提交文件不能只依赖 HEAD。证据放既有维护目录，不为迁移复制整仓库。
- 从目标项目引用的记忆索引定位独有上下文；只读取与此次范围相关的条目。发现来源缺失时记录缺口，不声称已完整迁移。

## 2. 区分规则、事实和历史

逐条判断旧内容的性质及落点，必要时用迁移表记录“来源 → 适用范围 → 去向 → 理由”：

| 内容 | 迁移处理 |
| --- | --- |
| 当前有效的协作规则、工程约束、验收标准 | 保留语义，归入入口或明确可达的专题规范 |
| 正在进行的任务、下一步、卡点与证据 | 保留在任务卡；入口只指向它，不另造一套状态 |
| IP、分支、设备版本、旧测试结论 | 标明时间和适用对象；用当前仓库或现场核验，不能升级为长期事实 |
| 单批、单次或单会话授权 | 保留原作用域；不转成未来永久授权，不重复索取本次已有有效授权 |
| 被后续决策修正的规则 | 用日期、对象和证据解释现行口径，保留旧记录的历史属性 |
| Claude 专属工具、记忆触发、权限配置 | 按第 5 步核能力和适配，不能机械替换工具名 |

当前明确用户指令优先于旧项目约定，同时遵守更高层指令与实际权限。无法判断的冲突列为待核实项，避免用“较新的文件”代替内容判定。只迁入与当前目标有关的偏好，不把某个项目的固件、提交、报告或目录约束推广到所有项目。

## 3. 按使用方式确定入口

确定用户实际从哪个目录启动、是否多个独立项目、是否继续用 Claude，以及 AI 文档能否进入代码仓库。能从指令和现有结构确定就直接实施，不为例行选型再设批准关卡。

- 单仓库可采用发现链内的 `AGENTS.md`；已有外置工作区可保留，明确如何从启动位置读取它。
- 多个独立项目采用分别可达的完整项目入口，或在用户接受共享入口时采用公共规则加项目差异。默认启动只进入选定项目。
- 用户要求外层无入口时遵从；项目入口须能独立工作，不依赖外层自动加载或兄弟入口补全规则。提供含入口路径的可靠启动提示，简称只作便利入口。
- 显式读取与自动发现是两种机制。外置、兄弟或任意嵌套目录里的 `AGENTS.md` 不因存在就保证被加载。结合启动位置、覆盖文件、当前客户端配置和官方说明核验，不为“让它加载”擅改全局配置。

涉及外置目录、多入口或双客户端时，读 [migration-patterns.md](migration-patterns.md) 的入口设计与兼容规则；需要起草入口时使用其中骨架，按项目裁剪。

入口最低承载以下语义：

1. **启动**：读目标项目入口 → 任务卡 → 核仓库状态 → 简报承接点、卡点和下一步。只有启动请求时完成恢复与简报；用户同时交代具体任务时继续已授权工作。
2. **按需读取**：具体任务再查地图、模块、决策、报告及源码；不在启动时整批加载历史和大件证据。
3. **实施**：保留项目关键契约、工具使用前提及真实验收标准，尤其是旧工作流依赖的设备或 UI 验证。
4. **收尾**：按既有规范更新任务卡、带日期进度和证据索引；决策、架构及长期规则按项目约定和有效授权维护。迁移事实写维护记录，不伪装成业务进展。

## 4. 保存独有记忆与接续信息

只有 Claude 私有记忆中存在的必要知识，应进入项目能访问、适合保存该内容的位置。参考 [migration-patterns.md](migration-patterns.md) 的记忆处理；为迁入项记来源、日期、适用项目和现行核实位置。

如需保全原文，使用冻结快照和按主题导航，明确“历史证据，不是当前执行指令”。新事实继续写项目正式台账，不维护两套活记忆。不批量迁移无关私有记忆、凭据或其他项目资料；含敏感信息的原件留在适当的受限位置，不复制进共享库。

任务卡只在确有需要时整理。按“下一位能否接手”判断信息是否足够，不为压行数删掉承重内容。收缩前保存唯一原文，保留当前状态、下一步、卡点和归档入口；未经授权不全面重写决策或架构。

## 5. 将旧能力要求映射到当前环境

逐项核验入口实际依赖的技能、浏览器、终端、构建机和设备工具。需要迁移工具或技能时读 [migration-patterns.md](migration-patterns.md) 的能力表。

- 技能保留一份权威源；在当前环境支持的发现目录使用指针或软链，不复制成多套规范。无法注册时可显式读 `SKILL.md`，准确标注“按路径可用，尚未验证自动发现”。本技能本身不依赖某个私人技能库。
- 将入口适配与技能行为适配分开：本技能不自动重写所有业务技能。用户另行要求适配技能时，先保全其质量契约和代表性旧产物，以同一材料在目标客户端实跑，核内容、视觉/交互或数据保全；格式通过、可发现和实际质量通过分别记录。
- Claude 的 slash 命令、插件、hooks 和 `.claude/settings*.json` 不自动成为 Codex 能力或权限。只迁移当前任务需要的等价能力，缺少工具时列出具体未验证项。
- 复用脚本先查写死路径、目标地址、版本、口令引用和副作用。不要为验证入口而刷设备、安装系统依赖或修改审批/沙箱设置。

入口发现和技能安装方式会变化；先查目标环境能力，再按需查官方 [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) 与 [技能发现](https://learn.chatgpt.com/docs/build-skills) 文档。记录已验证机制，不把当前客户端现象写成普遍保证。

## 6. 验收、交付与可恢复性

实施前用 [acceptance.md](acceptance.md) 选择适用验收项，完成后逐项留证。至少检查入口可达、重要规则与原文保全、任务未误启动、项目边界、引用、Git 基线和改动范围。

区分**静态检查、当前会话显式读取、新会话加载、真实工作流执行**。只报告实际完成的层级；没有新会话记录时，不把“文件存在”写成“自动加载成功”。无法启动新会话时交付精确启动提示与预期结果，将该项标为待验，而不是阻止已授权的其他工作。

交付说明包括：入口与调用方式、改了哪些文件、保全与验证证据、未验证事项及恢复方法。恢复前比较当前内容与迁移后清单；若已有后续修改，合并处理，不能用旧快照覆盖新工作或已生效的用户修订。提交、推送、全局安装及部署仅按本次有效授权处理，不从旧任务继承权限。
