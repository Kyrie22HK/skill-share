# AI 工作区搭建规范

> 沉淀自 rv1126（2026-05 首建）与 ssc375（2026-07-14 移植）两次实践。
> 目标：让 AI 跨 session 保留项目记忆——当前焦点、进度、决策、架构认知分文件持久化，新 session 按启动协议低成本恢复上下文。

## 一、终态目录形态（先对照这个，再动手）

```
<外层目录>/                      # 普通目录，非 git（如 ssc375/、rv1126/）
├── _ai_workspace/
│   ├── <项目名>/                # ★ 项目工作区（见"三、核心文件"）
│   │   ├── CLAUDE.md            # 协作规则 + 项目速览（核心入口）
│   │   ├── current_task.md      # 跨 session 接续点
│   │   ├── progress.md          # 里程碑与进度流水
│   │   ├── decisions.md         # 决策日志（只放模板，AI 绝不擅自写条目）
│   │   ├── architecture.md      # 架构地图（AI 首扫版 + ⚠️ 待确认）
│   │   └── (report/ patches/ postmortems/ learn/ …)  # 按需生长，不预建空目录
│   └── shared/                  # 芯片/平台级跨项目沉淀
│       ├── <芯片名>_notes.md    # 通用经验、陷阱
│       ├── glossary.md          # 术语表
│       ├── 工作报告_规格指针.md  # → 用户级 /work-report
│       └── 项目导览_规格指针.md  # → 用户级 /project-tour
└── <项目名>/                    # ★ git 仓库根（.git 在这里）
    └── <代码>
```

**三条硬性结构原则：**

1. **workspace 必须物理位于 git 仓库外**——个人 AI 文件绝不进团队仓库。若现状是"仓库根 = 项目根"（.git 在外层），**做目录重构**：`mkdir <项目名> && mv .git <代码目录> <项目名>/`，而不是用 `.gitignore`/`.git/info/exclude` 凑合（ssc375 教训：exclude 方案首版被用户否决，重构才是正解）。重构属目录结构决策，**先向用户提议、拍板后执行**；搬移前确认工作树干净，搬移后验证（见"五、验证"）。
2. **`<项目名>` 用真实项目名**（如 SSC375_IPC、AI_Camea_814），不是分支名、不是芯片名、不是临时代号——拿不准就**问用户**（ssc375 教训：AI 自选的分支名 ipc_hk 被更正为 SSC375_IPC）。工作区子目录与仓库目录同名。
3. **不设外层根 CLAUDE.md 薄指针**（用户明确偏好，保持各项目形式统一）。session 启动入口改由 **AI 项目记忆**承接：往记忆目录写一条 `<项目>-workspace-entry` 记忆，内容 = "每次新 session 先读 `_ai_workspace/<项目名>/CLAUDE.md` 并执行其启动协议"。

## 二、搭建流程

1. **读模板源**：优先参考最近一次搭建过工作区的项目实例，对齐文件格式与协议措辞；若本机无既有实例，本文档「三、核心文件规格」即完整权威规格（历史实例出处：rv1126 首建、ssc375 移植）。
2. **侦察新项目**（写速览/架构图的依据，半小时粒度即可）：构建体系（Makefile/CMake/入口）、SDK 与工具链、目录结构、既有项目文档（先读文档再读代码）、git 现状（分支/远端/commit/工作树）。**拿不准的一律标 ⚠️ 并集中进 architecture.md 的"待确认清单"，绝不编造**。
3. **必要时目录重构**（见结构原则 1，先拍板）。
4. **写核心文件**（见"三"）。
5. **建 shared/**：新建 `<芯片名>_notes.md` 与 `glossary.md` 初始骨架（工具链/构建体系/首批术语，其余随工作沉淀）；写 `工作报告_规格指针.md` 与 `项目导览_规格指针.md` 指向**用户级** skill（`~/.claude/skills/{work-report,project-tour}/`；权威源为 skill-share 仓库，用户级目录经软链指向本地 clone，2026-07-22 起）。**不要复制 skill 到项目级 `.claude/`**——同名项目级 skill 会盖住用户级新版，造成分叉（ssc375 教训）。
6. **写启动入口记忆**（见结构原则 3）。
7. **验证收尾**（见"五"）。

## 三、核心文件规格

### CLAUDE.md —— 协作规则与项目速览

节结构（按序）：启动协议 / 收尾协议 / 路径引用规则 / 项目速览 / 嵌入式特有约束 / 代码风格约定 / 协作禁区 / 参考索引。头部注明"协作规则由用户维护；速览由 AI 确认后更新"。

**启动协议**（逐字保留此语义）：① 读本文件 → ② 读 current_task.md（只含 active 大任务 + 归档一行索引）→ ③ architecture/progress/decisions/归档文件**一律不默认读**，按需 drill in → ④ 动手前向用户复述状态与计划，确认再动 → ⑤ 结束前执行收尾协议。

**收尾协议**：① 覆盖式更新 current_task.md → ② progress.md 追加带日期条目 → ③ 决策**先提议、用户确认后**才写 decisions.md → ④ architecture.md 过时处提议 diff → ⑤ 大任务收口归档为 `<任务名>_归档.md`，current_task 里替换为一行索引。

**路径引用规则**：统一相对 `<外层目录>/`，如 `SSC375_IPC/sdk/.../cgi_preview.c:120`；禁绝对路径、禁相对 `_ai_workspace/` 路径。

**项目速览**：芯片/项目类型/语言/目录形态与仓库范围/工作分支/主应用/构建方式/工具链/内核/SDK API 体系/关键组件/项目文档清单。全部来自侦察实证，推断处标 ⚠️。

**协作禁区**（固定项 + 项目项）：git commit/push 必须用户明确要求；不装系统依赖不动工具链；原厂 SDK 代码只读、改前先问；驱动/内核改前先问；不确定直接问不猜。

### current_task.md —— 当前焦点

头部规则三行（用途/规则/覆盖式更新）。正文：`## 🔥 Active` 大任务状态（做完什么/下一步/卡点）+ `## 已归档大任务索引`（表格：任务/状态/一句话结论/细节门户）+ `## 软待办` + `## 卡点/待用户` + 底部 `> ⚠️ 接入/环境` 备忘（板子连接/IP/账号/编译机）。

### progress.md / decisions.md / architecture.md

- **progress**：`## 当前里程碑` + `## 已完成`（倒序追加，日期开头）+ `## 进行中` + `## 待办/计划`。
- **decisions**：只放格式模板（问题/选项/决定/理由/影响范围），废弃决策保留并标注。**搭建时提议首条「建立 AI 工作区」待用户确认，不擅自写入**。
- **architecture**：头部声明"AI 首扫生成于 <日期>，可能误判，⚠️ 待用户校正"+ 扫描依据清单；正文 = 全局图景/目录树（带行内注释）/主应用分解/数据流推断；**尾部集中"待确认清单"供用户逐项销项**。

## 四、写作准则

- 全部中文（代码路径/命令除外）；信息密度优先，一行一事实。
- 每个文件头部三行注释：用途 / 更新规则（谁、何时、追加还是覆盖）。
- 实证与推断分离：侦察见到的直接写；推断必须挂 ⚠️。
- 历史条目不篡改：方案被否决时追加新条目说明"被否决、XX 优先"，不删旧记录。

## 五、验证与收尾（必做）

1. **git 完好**：`git status --short --branch`（干净+正常跟踪远端）、`git log --oneline -1`（commit 在）、目录重构后加 `git fsck`。
2. **引用无残留**：grep 工作区内旧路径/旧项目名（注意区分：分支名等 git 事实**不要**跟着项目名改）。
3. **目录对照**：最终 `ls` 与模板项目逐项对照（外层应只有 `_ai_workspace/`、`.claude/`、`<项目名>/`）。
4. **收尾汇报**（给用户的最终消息里必含）：最终目录树、与模板项目的差异及理由、decisions.md 首条提议全文、待确认清单去向、提醒 IDE 重载（仓库路径变了 git 插件会丢跟踪，重载窗口即恢复）。

## 六、已知坑速查

| 坑 | 处置 |
|---|---|
| 仓库根=项目根，workspace 放不到仓库外 | 目录重构下移一层（先拍板），勿用 exclude 凑合 |
| 用分支名/代号当项目名 | 问用户要真实项目名 |
| VS Code 移动 .git 后丢 git 管理 | 重载窗口即可；子目录仓库默认可被探测（同 rv1126），非结构问题 |
| Edit 工具改"被 mv 过的文件"报 not read | mv 后先 Read 再 Edit |
| 目录树 ASCII 图改名后注释列错位 | 改完目录名重排缩进对齐 |
| 无根 CLAUDE.md 导致 session 无入口 | 写 AI 项目记忆承接（结构原则 3） |
| 把 work-report 等 skill 复制到项目级 `.claude/` | 同名项目级会盖住用户级新版、日后分叉；一律用用户级 skill + shared/ 指针文件 |
