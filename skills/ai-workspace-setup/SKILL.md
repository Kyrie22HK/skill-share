# AI 工作区搭建规范

> 沉淀自 rv1126（2026-05 首建）与 ssc375（2026-07-14 移植）两次实践；2026-08-21 增补「根目录清爽化」目录形态与 WORKSPACE.md 维护规约（ssc375 目录重组实战回写），同日废止 shared/ 规格指针。
> 目标：让 AI 跨 session 保留项目记忆——当前焦点、进度、决策、架构认知分文件持久化，新 session 按启动协议低成本恢复上下文。

## 一、终态目录形态（先对照这个，再动手）

```
<外层目录>/                      # 普通目录，非 git（如 ssc375/、rv1126/）
├── _ai_workspace/
│   ├── <项目名>/                # ★ 项目工作区（见"三、核心文件"）
│   │   ├── AGENTS.md            # Codex / 双客户端的统一协作规则 + 项目速览
│   │   ├── CLAUDE.md            # 仅 Claude 时作为正文；双客户端时为可选兼容读取指针
│   │   ├── current_task.md      # 跨 session 接续点
│   │   ├── progress.md          # 里程碑与进度流水
│   │   ├── decisions.md         # 决策日志（只放模板，AI 绝不擅自写条目）
│   │   ├── architecture.md      # 架构地图（AI 首扫版 + ⚠️ 待确认）
│   │   ├── WORKSPACE.md         # 工作区地图 + 维护规约（根目录纪律/备份口径）
│   │   └── (archive/ history/ handover/ materials/ report/ test/ tools/ docs/ …)
│   │                            # 分类目录按需生长，不预建空目录；归属映射见结构原则 4
│   └── shared/                  # 芯片/平台级跨项目沉淀（只放真内容，不放 skill 规格指针）
│       ├── <芯片名>_notes.md    # 通用经验、陷阱
│       └── glossary.md          # 术语表
└── <项目名>/                    # ★ git 仓库根（.git 在这里）
    └── <代码>
```

**客户端与上下文**：先确认实际客户端、项目名、启动目录、代码仓库范围和既有文档约定；能从用户指令及现场确定的直接使用。不为使用 Codex 改变质量或授权边界。Codex / 双客户端用 AGENTS.md 作为规则正文；仅 Claude 可保留 CLAUDE.md 正文。二者共存时只维护一份规则，另一入口明确要求读取它，禁止循环导入。

**四条硬性结构原则：**

1. **workspace 必须物理位于 git 仓库外**——个人 AI 文件绝不进团队仓库。若现状是"仓库根 = 项目根"（.git 在外层），**做目录重构**：`mkdir <项目名> && mv .git <代码目录> <项目名>/`，而不是用 `.gitignore`/`.git/info/exclude` 凑合（ssc375 教训：exclude 方案首版被用户否决，重构才是正解）。重构属目录结构决策，**先向用户提议、拍板后执行**；搬移前记录分支、HEAD、工作树和构建/IDE/脚本路径依赖；保留现有修改，不自动清理，搬移后验证（见"五、验证"）。
2. **`<项目名>` 用真实项目名**（如 SSC375_IPC、AI_Camea_814），不是分支名、不是芯片名、不是临时代号——拿不准就**问用户**（ssc375 教训：AI 自选的分支名 ipc_hk 被更正为 SSC375_IPC）。工作区子目录与仓库目录同名。
3. **沿用本工作区体系的无外层根入口约定**，不靠新增 AGENTS.md 薄指针或改全局配置绕开。外置入口不一定在客户端发现链内：交付精确启动提示“先读 `_ai_workspace/<项目名>/AGENTS.md`，按启动协议启动项目”（仅 Claude 时替换入口名），并核实际启动目录。仅当客户端确有可写项目记忆机制且本次有授权时才登记记忆；不存在时用显式提示，不编造 Codex 的自动记忆文件或把文件存在当自动加载。
4. **工作区根目录只留 6 类协作核心文件（双客户端可加 1 个兼容指针）+ 分类目录，不留散件**（2026-08-21 ssc375 目录重组实战定型）。新产出一律直接落对应分类目录（目录不存在则建）：归档门户→`archive/`、快照/月卷/阶段备份→`history/`、对外交接件→`handover/`、原始资料原件→`materials/`、工作报告→`report/`、测试资产与证据→`test/<主题>_<日期>/`、脚本工具→`tools/`、项目说明文档→`docs/`、大件资产目录按需另设并在 WORKSPACE.md 登记。分类目录**按需建，不预建空目录**（不同项目需求不同，保留抽象性）——归属映射写进 WORKSPACE.md 维护规约，让「按需建」不退化成「随手扔根目录」。

## 二、搭建流程

1. **读模板源**：优先参考最近一次搭建过工作区的项目实例，对齐文件格式与协议措辞；若本机无既有实例，本文档「三、核心文件规格」即完整权威规格（历史实例出处：rv1126 首建、ssc375 移植）。
2. **侦察新项目**（写速览/架构图的依据，半小时粒度即可）：构建体系（Makefile/CMake/入口）、SDK 与工具链、目录结构、既有项目文档（先读文档再读代码）、git 现状（分支/远端/commit/工作树）。**拿不准的一律标 ⚠️ 并集中进 architecture.md 的"待确认清单"，绝不编造**。
3. **必要时目录重构**（见结构原则 1，先拍板）。
4. **写核心文件**（见"三"，6 类：AGENTS（仅 Claude 可用 CLAUDE）/ current_task / progress / decisions / architecture / WORKSPACE；双客户端可另加 CLAUDE 兼容指针）。
5. **建 shared/**：新建 `<芯片名>_notes.md` 与 `glossary.md` 初始骨架（工具链/构建体系/首批术语，其余随工作沉淀）。**shared/ 只放真内容，不生成 skill 规格指针**（2026-08-21 用户拍板废止：skill 本身即唯一真源、session 可用 skill 列表天然可发现，指针属纯冗余中间层且实测会烂、指向本机路径换机即失效）；skill 调用入口写进实际规则入口的参考索引（格式见"三"）。**不要复制 skill 到项目级 `.claude/`**——同名项目级 skill 会盖住用户级新版，造成分叉（ssc375 教训）。
6. **交付可执行的启动方式**（见结构原则 3），有条件再登记项目记忆；实际验证与待验项分开。
7. **验证收尾**（见"五"）。

## 三、核心文件规格

### AGENTS.md / CLAUDE.md —— 协作规则与项目速览

节结构（按序）：启动协议 / 收尾协议 / 路径引用规则 / 项目速览 / 嵌入式特有约束 / 代码风格约定 / 协作禁区 / 参考索引。头部注明"协作规则由用户维护；速览由 AI 确认后更新"。

**启动协议**（逐字保留此语义）：① 读本文件 → ② 读 current_task.md（只含 active 大任务 + 归档一行索引）→ ③ architecture/progress/decisions/归档文件**一律不默认读**，按需 drill in → ④ 动手前复述状态与计划；只启动时不执行旧待办，有明确任务则继续有效授权，缺关键目标信息才澄清 → ⑤ 结束前执行收尾协议。

**收尾协议**：① 覆盖式更新 current_task.md → ② progress.md 追加带日期条目 → ③ 决策**先提议、用户确认后**才写 decisions.md → ④ architecture.md 过时处提议 diff → ⑤ 大任务收口归档为 `<任务名>_归档.md`（落 `archive/`），current_task 里替换为一行索引 → ⑥ 顺手检查工作区根目录有无散件，清理或按归属归位（见结构原则 4）。

**路径引用规则**：统一相对 `<外层目录>/`，如 `SSC375_IPC/sdk/.../cgi_preview.c:120`；禁绝对路径、禁相对 `_ai_workspace/` 路径。

**参考索引**：列工作区各文件路径（含 WORKSPACE.md）；每个相关 skill 写一行调用入口，格式——「<用途>：读取 `<实际权威源>/SKILL.md`（已发现时 Codex 可 `$<skill名>`、Claude 可 `/<skill名>` 调用；产物落 <目录>）」。**不另设 shared/ 规格指针文件**（现成样例：ssc375 CLAUDE.md 参考索引，2026-08-21 改定版）。

**项目速览**：芯片/项目类型/语言/目录形态与仓库范围/工作分支/主应用/构建方式/工具链/内核/SDK API 体系/关键组件/项目文档清单。全部来自侦察实证，推断处标 ⚠️。

**协作禁区**（固定项 + 项目项）：git commit/push 必须用户明确要求；不装系统依赖不动工具链；原厂 SDK 代码只读、改前先问；驱动/内核改前先问；不确定直接问不猜。

### current_task.md —— 当前焦点

头部规则三行（用途/规则/覆盖式更新）。正文：`## 🔥 Active` 大任务状态（做完什么/下一步/卡点）+ `## 已归档大任务索引`（表格：任务/状态/一句话结论/细节门户）+ `## 软待办` + `## 卡点/待用户` + 底部 `> ⚠️ 接入/环境` 备忘（必要的接入位置与核实日期，不写密码/令牌；板子/编译机信息仅在该项目适用时记录）。

### progress.md / decisions.md / architecture.md

- **progress**：`## 当前里程碑` + `## 已完成`（倒序追加，日期开头）+ `## 进行中` + `## 待办/计划`。
- **decisions**：只放格式模板（问题/选项/决定/理由/影响范围），废弃决策保留并标注。**搭建时提议首条「建立 AI 工作区」待用户确认，不擅自写入**。
- **architecture**：头部声明"AI 首扫生成于 <日期>，可能误判，⚠️ 待用户校正"+ 扫描依据清单；正文 = 全局图景/目录树（带行内注释）/主应用分解/数据流推断；**尾部集中"待确认清单"供用户逐项销项**。

### WORKSPACE.md —— 工作区地图与维护规约

头部两行注释（用途："工作区每个顶层目录/文件是什么、归谁管、还活不活，目录不认识来这里查"；更新规则：维护规则见文末规约）。正文 = **目录登记表**：协作核心文件及可选兼容入口逐条一句话说明 + 已建分类目录逐条登记（放什么、索引入口）；新增顶层目录/大件资产时同步补登。文末「维护规约」**至少内置以下两条**（2026-08-21 ssc375 实战定型 + 用户拍板，保留语义）：

1. **根目录纪律**：根只保留协作核心文件与分类目录；新产出一律直接落对应目录（归属映射见结构原则 4，目录不存在则建）。临时文件可短暂落根，**用完即清或归入相应目录**——每次收尾协议顺手检查根目录有无散件。
2. **备份冗余口径**（用户原话「不需要做过多冗余」）：阶段备份只保留**唯一内容源**（删行/下架/清理等**删除动作前**的最后状态、最早基线——被删内容只存在于这些备份里）；**纯修改期中间备份**（改文本/换图/修正错值前的状态，改后即被正典取代、无独有内容）不留。删除非可再生文件仍需用户拍板，此条是对该类别的已拍板授权；拿不准某备份是否唯一内容源时单独问。

其余维护规约（如 current_task 收缩判据、progress 月分卷、报告索引同步）**不预置**，随项目实际需要长出（完整参考：ssc375 `WORKSPACE.md` 文末规约 7 条）。

## 四、写作准则

- 全部中文（代码路径/命令除外）；信息密度优先，一行一事实。
- 每个文件头部三行注释：用途 / 更新规则（谁、何时、追加还是覆盖）。
- 实证与推断分离：侦察见到的直接写；推断必须挂 ⚠️。
- 历史条目不篡改：方案被否决时追加新条目说明"被否决、XX 优先"，不删旧记录。

## 五、验证与收尾（必做）

1. **git 完好**：`git status --short --branch`（与进场基线相比仅有预期变化；无远端的本地仓库无需虚构跟踪关系）、`git log --oneline -1`（commit 在）、目录重构后加 `git fsck`。
2. **引用无残留**：grep 工作区内旧路径/旧项目名（注意区分：分支名等 git 事实**不要**跟着项目名改）。
3. **目录与启动对照**：按约定检查外置工作区、核心文件、引用和唯一规则源，不要求凭空创建 `.claude/`。显式读取入口 → 任务卡 → 核仓库 → 简报；有条件用新会话验证，并区分显式读取与自动发现。
4. **收尾汇报**（给用户的最终消息里必含）：最终目录树、与模板项目的差异及理由、decisions.md 首条提议全文、待确认清单去向、仅在实际移动仓库后提醒 IDE 重新定位/重载并核 Git 跟踪。

## 六、已知坑速查

| 坑 | 处置 |
|---|---|
| 仓库根=项目根，workspace 放不到仓库外 | 目录重构下移一层（先拍板），勿用 exclude 凑合 |
| 用分支名/代号当项目名 | 问用户要真实项目名 |
| VS Code 移动 .git 后丢 git 管理 | 重载窗口即可；子目录仓库默认可被探测（同 rv1126），非结构问题 |
| 改动或移动文件后仍按旧读取状态修改 | 重新读取现场文件，再用当前编辑工具修改 |
| 目录树 ASCII 图改名后注释列错位 | 改完目录名重排缩进对齐 |
| 无根入口导致新会话找不到规则 | 交付带实际路径的显式启动提示；可用项目记忆只是可选便利入口（结构原则 3） |
| 把 work-report 等 skill 复制到项目级 `.claude/` | 同名项目级会盖住用户级新版、日后分叉；一律用用户级 skill，调用入口写 CLAUDE.md 参考索引 |
| shared/ 放 skill 规格指针文件 | 2026-08-21 已废止——指针实测会烂、换机失效；skill 即唯一真源 |
| 产物随手扔工作区根目录 | 按根目录纪律归位（结构原则 4）；收尾协议末步检查散件 |
